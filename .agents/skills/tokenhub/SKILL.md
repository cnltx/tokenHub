# tokenHub 参考与运维

项目根目录位于本文件目录的 ../../..。先运行 node src/cli.js status，核对当前端口、数据目录和实例。新安装默认 3000，Windows 使用桌面快捷方式/start.vbs 隐藏启动，容器使用 Compose；读取 [运维文档](../../../docs/operations.md) 了解具体接口和启动参数。

## 转发规则

客户端始终收到请求的原模型结果。只有 forwarding 配置启用且源模型匹配时，后台额外发送相同完整请求到所选目标。结果丢弃，只记录元数据和 usage。目标可切换、来源可选全部或指定模型，无候选采纳和自动替换原响应。

源和目标用同一客户端身份鉴权。后台并发、健康和冷却按转发目标隔离，不能占主请求名额或污染主模型可用性。直接调用 Gateway 避免递归；目标自身跳过。中途取消和停止须传播到上游，正常主响应结束允许后台继续。

## 配置和数据

config.json 为非密钥元数据、secrets.json 为凭据引用；后台免登录，无账号、密码和管理密钥，保留同源及透明 CSRF 校验；使用稳定 ID，专用查看/导出以外保持脱敏。导出只用自身配置，不关联项目外目录。

data、临时数据、环境文件、导出和本地截图属于私有状态。打包或建仓时检查 .gitignore/.dockerignore 与待提交文件；保持 config.example.json/.env.example 为占位示例。

## 诊断与验证

模块或行为调整前读 [架构](../../../docs/architecture.md)。核对实际代码中的权限、有限重试、SSE 完成标记、取消、精确/未知 usage；记录状态码和 ID，凭据及正文保持在本地。

运行 node scripts/check.js 和 node test/run.js，使用本地模拟上游验证主响应不变、转发完整上下文、目标失败隔离、独立并发和停止落盘。Docker 变化还需构建/启动与持久化验证；桌面变化验证 wscript/Node 隐藏启动，不能声称未执行的测试已通过。
